# PATCHES.md — fork edit manifest

**The single source of truth for what is ours vs upstream's.** Every fork edit to an
upstream file gets a row here at the time it is written. Line anchors are as of
v3.14.3 (commit `29628c9`) unless marked otherwise and **will drift** — the "Anchor"
column names a stable neighbor symbol to re-find by, not a line number to trust.

Status values: `planned` → `landed` → (`drifted` → `landed`)* → `superseded-upstream` / `retired`.

**Anchors refreshed for v3.16.2 (vendor `3c5b2276`, series ported 2026-10-23 per ADR-031 / the ADR-030 intent-first loop).** The 3.16.1/3.16.2 vendor jumps superseded the whole 3.14.3-era perf family and the auth-session ports — see the Sync log and ADR-031 for the verdicts.

**Branch model (ADR-013, 2026-10-12): `main` = pure upstream mirror, zero fork commits; `patch/<release>` = working branch carrying the fork series. "Landed" SHAs below refer to their release's patch branch.**

**Intent model (ADR-030, 2026-10-23): `.fork/INTENTS.md` is the durable contract; the `Intent` column maps every row to the intentions it expresses. The sync loop is intention-first: on each vendor pull, check each intention against upstream — retire patches it now fulfills, re-express (adapt or rewrite) those it doesn't.**

NOT ported from the hydra line: exp-01..04 multi-account experiments (C-1, anchors deleted upstream — re-decide before promoting), the hydra-only AGENTS.md fork addendum (`09f37762`, self-scoped to hydra), `9bdcdd95` (depends on exp-01 registry). Official 3.15.2/3.15.3 ports U54–U58/ADR-025 (hydra/patch/3.15.3-only) are superseded-upstream at 3.16.2 — upstream carries them natively.**

**Hydra 3.16.x port provenance (ADR-032, 2026-10-23): the hydra dev lines carry the same shared series PLUS the promoted multi-account set U78–U83/N24–N25 (C-1 → I-11, hydra-only by design — the patch line does not carry it). On `hydra/patch/3.16.1` the shared series was replayed commit-by-commit onto vendor `0a1fc56d` (per-commit SHAs recorded in ADR-032, not duplicated per row); the U1–U77 rows' `landed (3.16.2: …)` SHAs remain the patch line's canonical anchors. `hydra/patch/3.16.2` needed no replay — the shared series is native there, so stop 2 = `patch/3.16.2` + the same promoted set (12 commits cherry-picked clean from stop 1; the only divergence from `patch/3.16.2` beyond the exp set is the fmt commit re-normalizing two series files to what 3.16.2's oxfmt actually wants).
